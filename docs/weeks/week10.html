Week 10 — Breaking Problems into Reusable Pieces

Functions · Parameters · Return Values

Today’s problem

Repeated code is not always repeated by a loop. Sometimes we need the same operation in different parts of a program.

How can we package one computational responsibility so that it can be reused and tested independently?

Learning goals

  • define and call a function;
  • distinguish parameters from arguments;
  • return a result;
  • separate calculation from display;
  • test a function with multiple cases;
  • identify hard-coded logic that ignores a parameter.

Part A — Core concept

def calculate_revenue(quantity, unit_price):
    revenue = quantity * unit_price
    return revenue

Before running:

  • What information enters the function?
  • What value leaves the function?
  • What changes if the arguments change?

Parameters are part of the contract

def apply_discount(price, rate):
    return price * (1 - rate)

Test:

print(apply_discount(500, 0.10))
print(apply_discount(500, 0.25))

Debug This

def calculate_area(width, height):
    area = width * 10
    return area

The code runs. What did the function fail to respect?

AI Verify

WarningVerification rule

The code below is syntactically valid and produces plausible output.
Do not run it immediately. First decide what you expect it to do.

Scenario: A product price should be increased using the tax rate passed to the function.

An AI assistant wrote:

def apply_tax(price, tax_rate=0.18):
    final_price = price * 1.18
    return final_price

Sample case: apply_tax(200, 0.08) should return 216.0.

Your verification sequence:

  1. Predict — What result will the function return, and why?
  2. Run — Run apply_tax(200, 0.08).
  3. Diagnose — Explain what the function signature promises and what the body actually does.
  4. Fix & verify — Repair the function so the parameter controls the calculation; verify with two tax rates.

This is not a prompting exercise. The target skill is verification of executable logic.
